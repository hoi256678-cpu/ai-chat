# 05. 숨은 금지어 찾기 (아호코라식)

시간 제한: 1초 | 메모리 제한: 256 MB

## 문제

03과 같은 문제다. 금지어 N개와 메시지 하나가 주어질 때,
메시지 **안에 등장하는 금지어의 총 횟수**를 구하라.

- 금지어끼리 겹치거나 포함되어도 **각각 센다.**
- 같은 금지어가 여러 위치에 나오면 **위치마다 센다.**

이번에는 04에서 만든 실패 링크로 **메시지를 앞에서부터 한 번만 훑는다.**
메시지의 글자를 다시 읽거나, 시작 위치마다 root로 돌아가지 않는다.

03보다 입력이 훨씬 크다. 03의 단순한 방법(시작 위치마다 트라이를 따라 내려가기)은 시간 초과가 난다.

## 입력

- 첫째 줄: N (1 ≤ N ≤ 1,000)
- 다음 N줄: 금지어 하나씩. 서로 다르다. 길이 1 이상 10,000 이하, **모든 금지어의 길이 합은 100,000 이하.**
- 마지막 줄: 메시지. 길이 1 이상 1,000,000 이하.
- 모든 문자열은 **알파벳 소문자**로만 이루어져 있다.

## 출력

메시지 안에 등장하는 금지어의 총 횟수를 출력한다.

## 예제 입력 1

```
4
he
she
his
hers
ushers
```

## 예제 출력 1

```
3
```

`she`(1~3), `he`(2~3), `hers`(2~5). 08장에서 손으로 따라간 그 예제다.

## 예제 입력 2

```
2
a
aa
aaaa
```

## 예제 출력 2

```
7
```

## 풀이 순서 (추천)

1. **트라이 + 실패 링크:** 04에서 짠 코드다. 복습 삼아 **04를 보지 않고 빈 화면에서 다시 짜 보자.** 막히면 그때 04를 연다.
2. **한 번 훑기:** 손으로 `ushers`를 따라갈 때 했던 그대로다.
   - 다음 글자로 갈 간선이 없으면 `cur`가 실패 링크로 **점프**한다. (`build_fail`의 while과 닮았다)
   - 노드에 도착할 때마다 **임시 포인터**로 실패 링크 사슬을 root까지 따라가며 `is_end`를 센다. 이때 `cur`는 움직이지 않는다.
3. 채점해 보면 거의 다 맞지만 **10번에서 시간 초과**가 날 것이다. 왜 느린지 생각해 보고 고친다. (생각해 볼 것 4번)

## 생각해 볼 것

1. 메시지 버퍼는 1,000,001칸이다. 어디에 두어야 할까? (04의 큐와 같은 고민)
2. 03에서는 정답이 `int`로 충분했다. 이번엔? (최악: 메시지가 `a` 100만 개, 금지어가 `a`, `aa`, `aaa`, … 446개. 길이 합이 100,000을 넘지 않는 가장 큰 경우다)
3. `cur`가 root에 있는데 그 글자의 간선도 없으면 어떻게 해야 할까?
4. 10번은 메시지가 `a` 100만 개, 금지어가 `a`×10000과 `a`×9999 + `b`다. `cur`가 `[a×10000]`에 있을 때 사슬을 몇 칸 따라가나? 그중 `is_end`인 노드는 몇 개인가? 전체로는? 그런데 노드마다 사슬에서 세는 개수는 **메시지와 상관없이 항상 같다.** 이걸 미리 계산해 둘 수 없을까? 계산 순서는 04의 BFS에서 힌트를 얻자.
