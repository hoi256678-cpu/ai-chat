# 코드 출처 구분: 바이브 코딩 vs 직접 작성

> 최종 업데이트: 2026-10-07

이 저장소의 코드는 두 가지 방식으로 만들어진다. 면접과 자소서에서 "내가 직접 짠 부분"을 정확히 말할 수 있도록 둘을 구분해 기록한다.

| 구분 | 표시 | 뜻 |
| --- | --- | --- |
| **바이브 코딩** | `바이브` | AI(Claude 등)가 코드를 작성하고, 사용자는 요구사항을 정하고 결과를 확인했다. |
| **직접 작성** | `직접` | 사용자가 개념을 공부하고 코드를 직접 타이핑했다. AI는 설명, 힌트, 리뷰, 테스트/채점기 제작만 했다. |

## 기준선

- 2026-10-07 커밋 `7aff87d`까지 앱 코드(`app/`, `components/`, `lib/`, `ml-service/`, `android-shell/`, `supabase/`)는 **바이브 코딩**으로 본다.
- 이 중 사용자가 직접 쓴 부분이 있다면 아래 목록에 추가해 바로잡는다.

## 표시 규칙

### 1. 파일과 함수에 표시

- 직접 작성한 알고리즘은 TypeScript로 옮길 때 **`lib/algorithms/`** 아래에 둔다. 이 폴더는 직접 작성 코드 전용이다.
- 직접 작성한 파일은 첫 줄에 이렇게 쓴다.
  ```ts
  // [직접 작성] <무엇> — 학습 기록: docs/study/algorithm-study-log.md §<장 번호>
  ```
- 바이브 코딩 파일 안에 직접 작성한 함수가 섞이면, 그 함수 바로 위에 같은 주석을 단다.
- AI가 작성한 테스트나 연결 코드(예: `lib/crisisDetection.ts`에서 직접 작성 함수를 불러오는 부분)는 표시하지 않는다. 표시가 없으면 바이브 코딩이다.

### 2. 커밋에 표시

커밋 메시지 끝에 `Code-Origin:` 줄을 붙인다.

| 커밋 내용 | 메시지 끝 |
| --- | --- |
| 직접 작성한 코드만 | `Code-Origin: 직접` (Claude 공동 작성자 줄을 붙이지 않는다) |
| AI가 작성한 코드나 문서 | `Code-Origin: 바이브` + `Co-Authored-By: Claude …` |
| 둘이 섞임 | 커밋을 둘로 나눈다 |

찾아보기:

```bash
git log --grep "Code-Origin: 직접"    # 직접 작성한 커밋만
git log --grep "Code-Origin: 바이브"  # 바이브 코딩 커밋만
```

`(로컬)` 표시는 아직 이 저장소에 없고 공부용 PC에만 있는 코드다.

## Claude가 지킬 것

- `[직접 작성]` 표시가 있는 코드와 `lib/algorithms/`의 알고리즘 본문은 Claude가 고치지 않는다. 문제를 찾으면 위치와 이유만 알려 주고 사용자가 고친다. 오타도 마찬가지다.
- 사용자가 직접 작성을 원하는 부분을 Claude가 대신 쓰게 되면, 그 코드는 `바이브`로 표시하고 이 목록에 넣지 않는다.
- 학습 기록(`algorithm-study-log.md`)과 자소서 소재에는 `직접` 표시된 코드만 "직접 구현했다"고 쓴다.
