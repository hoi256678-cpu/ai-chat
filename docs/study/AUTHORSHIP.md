# 코드 출처 구분: 바이브 코딩 vs 직접 작성

> 최종 업데이트: 2026-10-14

이 저장소의 코드는 두 가지 방식으로 만들어진다. 면접과 자소서에서 "내가 직접 짠 부분"을 정확히 말할 수 있도록 둘을 구분해 기록한다.

| 구분 | 표시 | 뜻 |
| --- | --- | --- |
| **바이브 코딩** | `바이브` | AI(Claude 등)가 코드를 작성하고, 사용자는 요구사항을 정하고 결과를 확인했다. |
| **직접 작성** | `직접` | 사용자가 개념을 공부하고 코드를 직접 타이핑했다. AI는 설명, 힌트, 리뷰, 테스트/채점기 제작만 했다. |

## 기준선

- 2026-10-07까지 이 저장소의 코드는 **전부 바이브 코딩**이다.
- 직접 작성은 알고리즘과 자료구조를 공부한 뒤, 사용자가 코드를 직접 쓰고 Claude에게 확인(리뷰)을 받으며 추가하는 코드부터 시작된다.

## 판단 기준: 대화 내용

기계적인 규칙이 아니라 **그 코드가 만들어진 대화**로 구분한다.

- 사용자가 직접 쓰고 Claude에게 확인을 받은 코드 → **직접**
- Claude가 쓴 코드 (사용자가 요청했더라도) → **바이브**
- 사용자가 쓴 코드에 Claude가 리뷰 의견만 줬고 사용자가 반영했다 → **직접**
- Claude가 사용자 코드를 대신 고쳐 줬다 → 그 수정분은 **바이브**
- 대화에 근거가 없는 변경(어디서 왔는지 모르는 코드) → 커밋 전에 사용자에게 한 번 묻는다

대화는 그 세션에만 남으므로, **확인해 준 바로 그 대화에서** 아래 표시와 목록을 남긴다. 나중에 다른 PC나 새 대화에서는 이 기록이 유일한 근거다.

## 기록 방법

### 1. 커밋에 표시

커밋 메시지 끝에 `Code-Origin:` 줄을 붙인다.

| 커밋 내용 | 메시지 끝 |
| --- | --- |
| 직접 작성한 코드만 | `Code-Origin: 직접` (Claude 공동 작성자 줄을 붙이지 않는다) |
| AI가 작성한 코드나 문서 | `Code-Origin: 바이브` + `Co-Authored-By: Claude …` |
| 둘이 섞임 | 커밋을 둘로 나눈다 |

```bash
git log --grep "Code-Origin: 직접"    # 직접 작성한 커밋만
git log --grep "Code-Origin: 바이브"  # 바이브 코딩 커밋만
```

### 2. 파일에 표시

- 직접 작성한 파일은 첫 줄에 `// [직접 작성] <무엇> — 학습 기록: docs/study/algorithm-study-log.md §<장 번호>`를 둔다. 바이브 파일 안의 직접 작성 함수는 그 함수 위에 같은 주석을 둔다.
- 이 한 줄은 사용자가 빠뜨렸으면 Claude가 추가해도 된다. 코드 본문은 건드리지 않는다.
- 알고리즘을 TypeScript로 옮길 때는 `lib/algorithms/` 폴더를 권장한다.

### 3. 직접 작성 목록에 한 줄 추가

## Claude가 지킬 것

- 사용자의 직접 작성 코드는 Claude가 고치지 않는다. 문제를 찾으면 위치와 이유만 알려 주고 사용자가 고친다. 사용자가 "고쳐 줘"라고 하면 고치되, 그 수정분은 바이브로 기록한다.
- 로컬에 커밋 안 한 변경이 있으면 GitHub 버전으로 덮어쓰지 않는다. 사용자가 직접 쓴 코드일 수 있으므로, 대화 내용으로 판단하고 근거가 없으면 먼저 묻는다.
- 학습 기록(`algorithm-study-log.md`)과 자소서 소재에는 `직접` 표시된 코드만 "직접 구현했다"고 쓴다.
